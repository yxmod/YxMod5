# YxMod5 安装与验证（阶段 0 / M0）

> 对应验证标准：`specs/2026-10-14-engineering-init-launch-chain/validation.md`
> 本流程由维护者手动验收；**不自动启动 `Human.exe`**。

## 1. 构建产物

> **重要**：当前《人类一败涂地》为 **32 位（x86）** 游戏，必须构建 `Win32` 平台（脚本默认值）。

执行一键构建：

```powershell
powershell -ExecutionPolicy Bypass -File build\build.ps1 -Platform Win32 -Clean
```

预期在 `release\` 得到：

- `winhttp.dll` —— 原生启动层（AheadLib 代理宿主）
- `YxMod5.dll` —— C# 模组层

## 2. 安装

1. 完全退出游戏（确认任务管理器中无 `Human.exe`）。
2. 将 `winhttp.dll`、`YxMod5.dll` 复制到游戏根目录（与 `Human.exe` 同级）。
   - 默认目录：`F:\SteamLibrary\steamapps\common\Human Fall Flat\`
3. 或使用脚本自动部署：

```powershell
powershell -ExecutionPolicy Bypass -File build\build.ps1 `
    -Platform Win32 `
    -Deploy -GameDir "F:\SteamLibrary\steamapps\common\Human Fall Flat"
```

部署脚本会读取 `Human.exe` 的 PE 架构（本作当前为 `x86`）并校验 `-Platform` 是否匹配。

| # | 验收项 | 观察方式 | 预期 |

## 5. 日志与崩溃排查

游戏目录下会生成两个日志文件（UTF-8，带时间戳与线程号）：

| 文件 | 内容 |
| --- | --- |
| `YxMod5_launcher.log` | 原生启动层：代理转发、进程校验、Mono 加载、C# 入口调用、未处理异常 |
| `YxMod5.log` | C# 模组层：宿主生命周期、Unity 警告/异常、AppDomain 未处理异常 |

Unity 自身日志位于游戏目录 `output_log.txt`（Unity 2017）。

**崩溃排查建议**：

1. 查看 `YxMod5_launcher.log` 最后一行，判断卡在哪个阶段；
2. 查看 `YxMod5.log` 最后一行，判断是否已进入托管层；
3. 原生未处理异常会在 `YxMod5_launcher.log` 中记录异常码、地址及所属模块
   （同时链式调用 Unity 原有的崩溃处理器）。

## 6. 常见问题

| 现象 | 排查 |
| --- | --- |
| 无控制台窗口 | 确认进程名为 `Human.exe`；确认 `winhttp.dll` 位于游戏根目录 |
| 控制台有日志但无宿主 | 检查 `YxMod5.dll` 是否与 `Human.exe` 同级；查看 `Player.log` 异常 |
| 游戏网络异常 | 检查 `winhttp.dll` 导出是否完整（`dumpbin /exports` 应为 70 个） |
| 其它程序异常 | 本代理仅对 `human.exe` 注入；如仍有问题，确认未把 DLL 放入系统目录 |
