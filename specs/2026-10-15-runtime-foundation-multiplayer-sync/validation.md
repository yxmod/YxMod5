# 阶段 1：自研运行时基础与多人同步设计 — 验证标准（Validation）

> - 所属分支：`feat/stage-1-runtime-foundation-multiplayer-sync`
> - 对应 roadmap：阶段 1，任务 `1.1`–`1.8`
> - 编写依据：`specs/mission.md`、`specs/tech-stack.md`

## 1. 验证方式

分两类：

1. **自主验收项**：由开发助手（本会话）自主完成 —— 构建、离线编码往返、静态检查等，无需进入游戏。
2. **手动验收项**：依赖 `human.exe` / Mono / 多人对局，由**维护者（用户）**按下方步骤真机验收。

前置条件（手动项）：将构建产物 `winhttp.dll` + `YxMod5.dll` 放入游戏目录。**本流程不自动启动 `human.exe`**，游戏启动与真机观察由维护者自行完成。

## 2. 验收清单

### 2.1 自主验收项（开发助手执行）

1. **构建通过**：`src/mod/YxMod5.csproj`（.NET Framework 4.8）与 `src/launcher/YxMod5Launcher.vcxproj`（Win32/x64）均可成功生成。
2. **访问器核心**：对测试类型做读写往返，委托化调用结果与 `Invoke` 一致；不存在成员/空对象/类型错误均被防护层安全降级。
3. **编码往返**：自定义消息经 `NetStream` 编码后解码，`MsgId` / `NetId` / 字符串 / 子流字段一致（离线自测，不依赖游戏进程）。
4. **配置系统**：INI 读写与持久化逻辑离线可验证（临时目录模拟 `YxMod5\`）。
5. **目录与文件**：`<游戏根目录>\YxMod5\` 的创建逻辑与配置/日志落盘路径正确（代码检查）。

### 2.2 手动验收项（维护者执行）

> 以下为维护者在真机上的操作步骤。

1. **目录与配置**：启动游戏后，确认游戏根目录下自动创建了 `YxMod5` 文件夹，且模组日志/配置文件位于该文件夹内。
2. **访问器真机**：进入任意关卡，确认本地 `Human` 状态/刚体可被访问器读取，日志可观测，无空引用崩溃。
3. **多人访问器**：进入多人房间，确认能区分房主/客户端/本地玩家，玩家列表可遍历（日志可观测）。
4. **热键**：按下示例热键，确认回调触发、日志可观测；组合键/数字编号按框架约定生效。
5. **同步收发（本地）**：单人（本地）场景下发送/接收自定义消息，确认闭环不崩溃（日志可观测）。
6. **同步收发（多人）**：房主 + 至少 1 名客户端对局，客户端发送请求 → 房主校验并广播 → 其他客户端收到自定义消息（日志可观测），非法消息被丢弃且不影响对局。

## 3. 完成定义（DoD）

阶段 1 **完成** = 以下条件**同时满足**：

- 上述「自主验收项」第 1–5 项全部通过；
- 上述「手动验收项」第 1–6 项全部通过；
- 维护者明确表示「**验收通过**」。

## 4. 合并标准

- 仅在维护者**明确表示「验收通过」后**，才允许：
  1. 更新进度（`specs/roadmap.md` 阶段 1 勾选、`README.md` 当前进度）；
  2. 将本分支 `feat/stage-1-runtime-foundation-multiplayer-sync` 合并回 `main`。
- 在维护者给出「验收通过」之前，本分支保持独立，**不得合并、不得更新进度**。
- 若验收中发现问题，记录问题并修复后重新执行验收清单，直至全部通过。
